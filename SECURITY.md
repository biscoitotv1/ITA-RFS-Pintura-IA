# Política de Segurança

## Reportando vulnerabilidades

Se você identificar uma vulnerabilidade, falha sensível ou risco de segurança:

1. não publique a falha imediatamente;
2. descreva o problema com clareza;
3. inclua impacto potencial, passos de reprodução e evidências relevantes;
4. encaminhe o reporte de forma privada aos mantenedores do projeto.

## Escopo

Esta política vale para:

- código-fonte;
- configurações;
- integrações;
- fluxos operacionais documentados no repositório.

## Boas práticas esperadas

- reporte responsável;
- compartilhamento mínimo necessário de informações sensíveis;
- validação antes de divulgação pública;
- colaboração para correção e mitigação.

## Observação

Caso o projeto passe a utilizar um canal oficial de segurança, este documento deve ser atualizado com o contato e o processo formal.
